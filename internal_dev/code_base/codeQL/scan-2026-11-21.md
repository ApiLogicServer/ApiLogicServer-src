## New since 2026-11-13 (83 -> 87 found -> 86)
1. **log-injection, `samples/basic_demo_eai/api/api_discovery/order_b2b_service.py:66` - real (CWE-117), fixed.**
   The B2B request log (new 11-19) logged the partner-supplied `Account` unescaped, so a partner could put a line break in
   it and forge a line in `logs/als.log`. Fix: log it through the existing `api_utils.safe_log()` (strips line breaks,
   as the August log-injection fixes did). Verified live after the fix with `"Account": "Alice\nINFO FORGED LINE"`: the
   value stays on one line, no forged line appears (HTTP 400, rejected as an unknown customer). Not reproduced before the fix.
   Project CE 3.72 now says to log partner values through `api_utils.safe_log()`, so new builds do it.
2. **stack-trace-exposure, `prototypes/base/integration/system/EaiDebug.py:167` (+ the basic_demo_eai copy) - by design.**
   Option (b) (11-20): the simulated consume returns `str(e)` for business rejections only (`LookupNotFound`,
   `ConstraintException`), e.g. "no Customer found where name == ..."; every other exception still returns the generic
   "simulation failed - see logs/als.log". The text is a business message, not a traceback, and the endpoint is
   dev-only (no auth, off when `APILOGICPROJECT_CONSUME_DEBUG` is false). Same disposition as the samples' constraint messages.
3. **jinja2 autoescape, `samples/basic_demo_eai/api/api_discovery/dashboard_services.py:98` - by design.** The new
   order-flow dashboard renders chart JSON into a Chart.js page; autoescape would break it. Same as nw `dashboard_services.py`.
   The rendered values are rule-maintained numbers and fixed labels, not user text.

No regression: the August path-injection (admin_loader) and log-injection (customize_api, auth providers) fixes hold,
the 17.05.24 CLI password-log fix holds, and the 11-13 `llm_client.py` hostname fix holds (no CWE-020 findings).
Query pack 1.9.1 raised nothing new against unchanged code: every new finding is in code added since 11-13.
