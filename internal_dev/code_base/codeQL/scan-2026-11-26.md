## Note: change CodeQL does not rate (security-relevant, reviewed by reading the diff)
`security/system/authentication.py` (base + all samples): `JWT_SECRET_KEY` was the literal `"ApiLogicServerSecret"`; it is
now `Config.SECRET_KEY or "ApiLogicServerSecret"` (the same literal as a fallback), and for the SQL provider (HS256)
the server exits at startup if the secret is a shipped placeholder and `APILOGICPROJECT_ENV` is not `dev`. So the literal
still exists in the source as a dev fallback; the change is that pre-prod and prod refuse to run with it. This
suite does not include a hard-coded-credentials query that flagged it before or flags it now, so "no finding" here says
nothing either way about the literal; the protection is the startup guard, which this scan did not exercise.
